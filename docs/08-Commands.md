# Консольные команды

Бандл предоставляет набор консольных команд для управления ботом. Все команды используют
access token из конфигурации Symfony — вводить его вручную не нужно.

## Обзор

```bash
php bin/console list max-bot
```

| Команда | Описание |
|---|---|
| `max-bot:run-polling` | Запуск бота в режиме long polling |
| `max-bot:debug` | Long polling с выводом сырых событий |
| `max-bot:chats` | Список чатов бота |
| `max-bot:delete-chats` | Удаление чатов, где бот является владельцем |
| `max-bot:subscribe` | Регистрация webhook-подписки |
| `max-bot:subscriptions` | Просмотр активных webhook-подписок |
| `max-bot:unsubscribe` | Удаление webhook-подписки |

---

## max-bot:run-polling

Запускает бота в режиме long polling: обрабатывает входящие события через зарегистрированные
обработчики (`MaxBotHandlerInterface`). Подробнее — в разделе [Long Polling](05-LongPolling.md).

```bash
php bin/console max-bot:run-polling [--limit=100] [--timeout=60]
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--limit` | `100` | Максимальное количество событий за запрос (1–1000) |
| `--timeout` | `60` | Время ожидания ответа сервера в секундах (0–90) |

---

## max-bot:debug

Запускает long polling и выводит каждое входящее событие в виде отформатированного JSON.
Обработчики событий при этом не вызываются — команда работает напрямую с `MaxApiClient`.

Перед запуском проверяет наличие активных webhook-подписок: если они есть, long polling
невозможен и команда завершается с предупреждением.

Команду можно запускать параллельно с `max-bot:run-polling` — каждая ведёт независимую
сессию с собственным маркером, поэтому обе получают все входящие события. Это позволяет
наблюдать сырые данные в одном терминале, пока бот обрабатывает события в другом.

```bash
php bin/console max-bot:debug [--limit=1] [--timeout=60]
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--limit` | `1` | Максимальное количество событий за запрос (1–1000) |
| `--timeout` | `60` | Время ожидания ответа сервера в секундах (0–90) |

Пример вывода:

```
 Событие #1
============

 Тип    : message_created (message_created)
 Время  : 2026-05-29 10:00:00

{
    "update_type": "message_created",
    "timestamp": 1748512800000,
    "message": { ... }
}
```

Остановка: `Ctrl+C` или `SIGTERM`.

> Команда полезна при разработке для проверки, что бот получает события нужного типа.

## max-bot:chats

Выводит список чатов бота в виде таблицы с поддержкой постраничной навигации.

```bash
php bin/console max-bot:chats [--per-page=5]
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--per-page` | `5` | Количество чатов на странице (1–50) |

В таблице отображается: ID, название, тип, статус, количество участников, является ли бот
владельцем, время последнего события.

---

## max-bot:delete-chats

Выводит список чатов, где бот является владельцем, и позволяет интерактивно их удалять.

```bash
php bin/console max-bot:delete-chats [--per-page=5]
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--per-page` | `5` | Количество чатов на странице (1–50) |

После вывода таблицы команда спрашивает:

```
Номер чата для удаления, "all" для удаления всех на странице, или Enter для пропуска:
```

- Введите номер строки из таблицы — будет запрошено подтверждение и удалён один чат
- Введите `all` — удалятся все чаты на текущей странице (каждый с подтверждением)
- Нажмите `Enter` — переход к следующей странице

> Удаление необратимо. Команда запрашивает подтверждение (`yes/no`) перед каждым удалением.

## max-bot:subscribe

Регистрирует webhook-подписку: сообщает серверам Max адрес, на который отправлять события.

```bash
php bin/console max-bot:subscribe [<url>] [--secret=...] [--types=all]
```

| Аргумент / параметр | Обязательный | Описание |
|---|---|---|
| `url` | нет | HTTPS-адрес webhook без порта. Если не указан — определяется автоматически или запрашивается |
| `--secret` | нет | Секретный ключ (5–256 символов, `A-Za-z0-9_-`). Запрашивается интерактивно, если не указан |
| `--types` | нет | Типы событий через запятую или `all` (по умолчанию: `all`) |

### Автоопределение URL

Если аргумент `url` не передан, команда пытается сгенерировать адрес из маршрута `max_bot_webhook`
через Symfony Router. Для этого в `config/packages/framework.yaml` должен быть настроен `default_uri`:

```yaml
framework:
    router:
        default_uri: 'https://your-domain.com'
```

При корректно настроенном `default_uri` команда выведет обнаруженный адрес и предложит его
принять или ввести другой:

```
 Обнаружен маршрут webhook: https://your-domain.com/max-bot/webhook
 Webhook URL (https://, без порта) [https://your-domain.com/max-bot/webhook]:
 >
```

Если `default_uri` не задан или маршрут `max_bot_webhook` не зарегистрирован (используется
собственный маршрут), команда просто попросит ввести URL вручную.

### Примеры

```bash
# URL определяется автоматически (если настроен default_uri)
php bin/console max-bot:subscribe

# Явно указать URL
php bin/console max-bot:subscribe https://example.com/max-bot/webhook

# Указать секрет и типы событий в параметрах
php bin/console max-bot:subscribe https://example.com/max-bot/webhook \
    --secret=my-secret-key \
    --types=message_created,bot_started,message_callback
```

Доступные типы событий можно посмотреть в SDK:
`MaxMessenger\Bot\Model\Enum\UpdateType`.

> URL должен начинаться с `https://` и не содержать порт.

## max-bot:subscriptions

Выводит таблицу всех активных webhook-подписок бота.

```bash
php bin/console max-bot:subscriptions
```

Пример вывода:

```
 Webhook-подписки
==================

 # │ URL                                      │ Дата создания       │ Версия API │ Типы событий
───┼──────────────────────────────────────────┼─────────────────────┼────────────┼──────────────
 1 │ https://example.com/max-bot/webhook      │ 2026-05-29 10:00:00 │ 0.0.30     │ все
```

---

## max-bot:unsubscribe

Выводит список активных подписок и удаляет выбранную.

```bash
php bin/console max-bot:unsubscribe
```

Команда показывает таблицу подписок, затем спрашивает номер для удаления:

```
Введите номер подписки для удаления (1–N) или 0 для отмены [0]:
```

После выбора запрашивается подтверждение. При успехе подписка удаляется немедленно — Max
перестанет отправлять события на этот URL.

> После удаления подписки можно запустить `max-bot:run-polling` или `max-bot:debug` для
> получения событий через long polling.
